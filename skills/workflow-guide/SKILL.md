# 统一入口与恢复

先定位真实项目与当前成果，再把明确请求交给一项适用能力；导航不是另一套执行流程。用中文简短回答。来源及裁剪见 [NOTICE.md](NOTICE.md)。

## 定位与判断

1. 读项目 AGENTS.md、已有 docs/workflow/state.yaml、overview，以及指向迭代的 scope/design/tasks/verification；按需核对 specs、foundation、releases 与实际产物。框架 docs/design 和 templates/project 不是业务需求。空占位文件合法，不为导航补整套文档。
2. 对照用户本次明确指定、具体开轮/暂停/恢复确认及实际scope/tasks/verification。state只作可能过时的线索，不写入；不按最大编号、最近修改、唯一未完成或未标暂停的目录选当前轮，草案不是活跃工作。已有明确依据不重复询问；多个合理项目、记录缺失/部分写入或冲突且无法消解时，列出影响并只澄清受影响部分。
3. 区分有效规格、本轮获准变更和目标内容/运行版本。草案、完成勾选、旧检查及子 Agent 自报不等于当前通过或用户验收。已有明确确认不重复索取。

| 用户现在要什么 | 对应接续 |
| --- | --- |
| 只问进度、哪里出问题、下一步 | 只读报告当前成果、已有事实、阻塞和建议，不写文件或启动工作。 |
| 想法、反馈、范围与方案 | clarify-design；仅需比较取舍时 discuss-design。 |
| 明确开启后续迭代并整理资料 | 交主Agent使用clarify-design核对开轮条件和真实路径，只准备获准资料；不因无当前迭代就自动创建。 |
| 明确暂停切换、恢复记录或维护已确认overview | 交主Agent使用clarify-design完成必要记录或概览维护，保留原验收事实；只查询时仍只读。 |
| 已有范围方案，需要任务安排 | plan-tasks。设计与计划可联合准备，不当作批准实施。 |
| 已批准当前任务，要求实施或继续 | execute-task；当前已提交而未明确验收时，返回验收入口并等待。 |
| 已确认的最小工程 | build-foundation，仍按当前成果的执行和验收规则。 |
| 只审查、只测试、只诊断 | review-work、test-work、debug-issue，按请求限制读写。 |
| 发布准备或具体部署 | release-work；准备不等于部署授权。 |
| 线上问题 | handle-incident，必要信息未齐先询问，再在访问授权内调查。 |

无当前迭代时，目标已获具体确认则按原授权接续；未定时推荐候选与理由供选择，无候选则询问目标。明确开轮或切换请求交上述资料分支，不把入口变为写入者。明确暂停可保留待验收成果后切换，原验收不自动通过；没有该指令仍停在等待点。线上修复的迭代安排和基线不走普通开轮例外，交原故障流程说明缺项；Git事项留独立专题，不自行决定策略或操作。

需要推荐后续目标时，先读取已有 docs/project/backlog.md，结合 overview、用户本次意图及任务和验收记录，区分未选候选、已纳入工作和已完成事项。给出候选的出处、推荐原因及关键待确认取舍；已完成条目不重复当新任务，草案不当作已获准下一轮。backlog为空或缺失时利用其他可得依据，仍无候选才问目标；读取受阻须说明缺口，不能称待办为空。推荐和用户选中想法都不自动批准未展示的范围、方案或实施；查询不改backlog或其他文件，当前成果待验收时仍保留原等待点。

## 恢复与交接

恢复前核对中断点、实际文件及外部动作结果；不凭旧计划重放写入、部署、回退或迁移。外部动作结果未知时，先按已有访问授权查询；无法确认就保留未知，不能当未执行重试。已有验收而规格收尾中断时，交 execute-task 仅补未完成收尾，不重复实施或索取相同验收。

暂停或开轮资料尚未写全时，报告已写/未写和确认依据；用户要求补完才交clarify-design恢复最小记录。明确恢复旧轮时，核对现轮暂停和旧轮恢复是否已有记录，缺项由原主流程按同一请求补齐后再判断任务接续；恢复记录不是实现或验收通过。专项返回原主流程，不能循环调用入口或把记录补齐当作新一轮实施批准。

交接一份材料：项目与当前成果、请求模式、目标内容/运行版本、原始要求和具体确认、允许读写及副作用、可复用证据与适用性、未决项、返回位置。先确认能力真实可用并读完整说明；不可用就给材料及缺口，不伪称调用或安装上游。

当前主 Agent 保留记录和结果责任；被调用能力返回方法与证据，不能递归启动另一套入口或执行流程。已有测试/审查可在内容与环境仍适用时复用，变化后只补受影响检查。正式记录沿原 tasks/verification、设计及发布归属；无适用位置在对话交付。

例如“继续之前工作”遇到 T1 已实现待验收、T2 未开始时，说明 T1 的体验入口与待验收事实，等待明确结果；既不推进 T2，也不把候选行为提前写为有效规格。
