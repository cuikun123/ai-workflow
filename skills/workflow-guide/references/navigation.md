# 定位当前工作

开始、继续或推荐下一目标时读取。进度查询先用[只读工具](common/runtime-query.md)，遇到位置/依据不一致再读本参考所需部分。依据与交接规则分别见[工作契约](common/work-contract.md)和[写入契约](common/write-contract.md)。

## 定位与判断

只读定位只加载本入口、最小状态和当前相关业务记录。推荐后续能力时可按原生发现元数据说明用途；当前并未调用该能力，就不要为候选读完整clarify、foundation、planning或整组Skill。真正交给专项时才按需读取提供者入口与参考。需要安装/工作流核对或交接固定能力时运行项目内只读`check`，独立小修改不为此加载状态；失败只报告缺项和影响，不把正确状态格式或一次模型答复当作安装完整。

Windows PowerShell优先用Node按UTF-8读取当前必需文件并输出JSON；用单引号here-string管道传入脚本可避免嵌套引号损坏。受限只读会话不要设置Console或OutputEncoding。实际输出乱码时停止猜测，仅将乱码的必需文件以ASCII转义JSON重读一次；不批量重读候选技能，不因编码失败扩大读取范围。

1. 先核对项目AGENTS和明确目标。只有当前请求依赖工作流位置时才读state，按需要读overview和指向迭代的scope/design/tasks/verification；按需核对 specs、foundation、releases 与实际产物。框架 docs/design 和 templates/project 不是业务需求。空占位文件合法，不为导航补整套文档。
2. 对照用户本次明确指定、具体开轮/暂停/恢复确认及实际scope/tasks/verification。state须与真实依据核对，受管写入由原主流程通过工具维护；不按最大编号、最近修改、唯一未完成或未标暂停的目录选当前轮，草案不是活跃工作。已有明确依据不重复询问；多个合理项目、记录缺失/部分写入或冲突且无法消解时，列出影响并只澄清受影响部分。
3. 区分有效规格、本轮获准变更和目标内容/运行版本。草案、完成勾选、旧检查及子 Agent 自报不等于当前通过或用户验收。已有明确确认不重复索取。

| 用户现在要什么 | 对应接续 |
| --- | --- |
| 只问进度、哪里出问题、下一步 | 只读报告当前成果、已有事实、阻塞和建议，不写文件或启动工作。 |
| 想法、反馈、范围与方案 | clarify；仅需比较取舍时 design_discussion。 |
| 明确开启后续迭代并整理资料 | 交主Agent使用clarify核对开轮条件和真实路径，只准备获准资料；不因无当前迭代就自动创建。 |
| 明确暂停切换、恢复记录或维护已确认overview | 交主Agent使用clarify完成必要记录或概览维护，保留原验收事实；只查询时仍只读。 |
| 已有范围方案，需要任务安排 | planning。设计与计划可联合准备，不当作批准实施。 |
| 已批准当前任务，要求实施或继续 | implementation；当前已提交而未明确验收时，返回验收入口并等待。 |
| 已确认的最小工程 | foundation，仍按当前成果的执行和验收规则。 |
| 只审查、只测试、只诊断 | review、testing、diagnosis，按请求限制读写。 |
| 发布准备或具体部署 | release；准备不等于部署授权。 |
| 线上问题 | incident，必要信息未齐先询问，再在访问授权内调查。 |
| 框架升级 | 默认当前任务验收及适用Git收尾后，再按clarify/planning准备独立升级任务；先核对范围、项目固定版本和工具，不自动安装或将待验收记为通过。 |

无当前迭代时，目标已获具体确认则按原授权接续；未定时推荐候选与理由供选择，无候选则询问目标。明确开轮或切换请求交上述资料分支，不把入口变为写入者。明确暂停保留原验收状态，没有该指令仍停在等待点。普通任务起步、暂停保存、PR验收收尾及重复Git请求，由原主Agent读取实际可用的implementation完整Git操作方法核对实际状态和适用授权；只读查询可核对Git状态，但不因此提交或切换。入口不执行另一套Git流程；缺能力交付缺项。线上修复的迭代安排、实际运行基线和返回约定走incident，不套普通开轮。

需要推荐后续目标时，先读取已有 docs/project/backlog.md，结合 overview、用户本次意图及任务和验收记录，区分未选候选、已纳入工作和已完成事项。给出候选的出处、推荐原因及关键待确认取舍；已完成条目不重复当新任务，草案不当作已获准下一轮。backlog为空或缺失时利用其他可得依据，仍无候选才问目标；读取受阻须说明缺口，不能称待办为空。推荐和用户选中想法都不自动批准未展示的范围、方案或实施；查询不改backlog或其他文件，当前成果待验收时仍保留原等待点。
