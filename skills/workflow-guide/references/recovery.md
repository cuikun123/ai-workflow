# 中断与交接

实际有暂停、写入中断或结果未知时读取。先用[查询与诊断](common/runtime-query.md)，v2规格收尾依[规格工具](common/spec-runtime.md)，已有v1状态依[原状态协议](common/state-runtime.md)，显式版本操作依[版本方法](common/version-runtime.md)。

## 恢复与交接

恢复前核对中断点、实际文件及外部动作结果；不凭旧计划重放写入、部署、回退或迁移。外部动作结果未知时，先按已有访问授权查询；无法确认就保留未知，不能当未执行重试。已有验收而规格收尾中断时，交 implementation 仅补未完成收尾，不重复实施或索取相同验收。

暂停或开轮资料尚未写全时，报告已写/未写和确认依据；用户要求补完才交clarify恢复最小记录。明确恢复旧轮时，核对现轮暂停和旧轮恢复是否已有记录，缺项由原主流程按同一请求补齐后再判断任务接续；恢复记录不是实现或验收通过。专项返回原主流程，不能循环调用入口或把记录补齐当作新一轮实施批准。

交接一份材料：项目与当前成果、请求模式、目标内容/运行版本、原始要求和具体确认、允许读写及副作用、可复用证据与适用性、未决项、返回位置。先核对能力表与完整安装，按当前动作读提供者入口和参考；不可用就给材料及缺口，不伪称调用或安装上游。

涉及Git时一并交接真实仓库与worktree路径、任务分支/HEAD、同步/推送/PR目标、暂存及其他来源改动归属、实际保存和远端结果、验收与合入事实。恢复或重复请求先核对真实引用及平台状态，结果未知先查证，只接续获准剩余步骤，不重造提交/PR或以“继续”补记验收。

当前主 Agent 保留记录和结果责任；被调用能力返回方法与证据，不能递归启动另一套入口或执行流程。已有测试/审查可在内容与环境仍适用时复用，变化后只补受影响检查。正式记录沿原 tasks/verification、设计及发布归属；无适用位置在对话交付。

例如“继续之前工作”遇到 T1 已实现待验收、T2 未开始时，说明 T1 的体验入口与待验收事实，等待明确结果；既不推进 T2，也不把候选行为提前写为有效规格。
