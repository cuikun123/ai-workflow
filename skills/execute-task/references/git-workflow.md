# 获准的Git操作

仅在本项目、本任务实际Git操作已有适用授权时读取；默认设置不是创建仓库、配置作者、推送或合入许可。权限与历史保护依[写入契约](common/write-contract.md)。

## Git操作方法

这是主Agent使用真实Git与平台工具的方法，不是安装器、Git服务或权限沙箱。受托实施者、测试者和审查者只在分配范围返回结果，不自行提交、合入或清理。新个人项目默认GitHub、私有仓库、origin/main；已有项目沿用实际平台、可见性与名称。默认值不授权创建仓库或改名；多远端分别核对同步、推送、PR目标及账户，不能凭origin名称猜地址。

框架升级也是独立任务，默认本任务验收及适用收尾后再安排；只更新受管理资源和必要导航，保留业务资料、用户修改与进度，涉及业务代码/依赖/构建变更另行说明确认。在既有tasks/verification区分升级前实际版本、目标及升级后核实版本，未知不补造；不因此实现安装器或通用回退机制。

### 任务起步

1. **核对实际位置。** 读`git status --short`、`git branch --show-current`、`git worktree list --porcelain`及项目远端/主分支配置。只检查本次涉及目录：主目录在同步前、需保存暂停的旧任务目录、新任务目录在开工前，以及实际要保存/切换/使用的其他目录。核对暂存、未暂存、新文件与未解决冲突；忽略的依赖缓存可保留，不扫描整理无关任务目录。
2. **保存已有改动。** 按下一节核对归属和入库许可，同任务允许内容可一起保存，其他任务分开处理；不清空、丢弃或混入当前提交。未明归属保留现场，只澄清受影响部分。新任务依赖的干净条件未满足则不开始；已保存暂停目录与需保留的冲突现场不因别处开任务被清理。
3. **同步主分支。** fetch已明确的远端主分支，核对本地主分支与本次获取提交。已一致保持，仅落后时在主目录用`git merge --ff-only <远端主分支引用>`快进；再核对提交一致。领先或分叉先查原因，不覆盖本地提交、不为同步制造Merge；无法确认最新远端状态则报告，暂不从旧基线开任务。缺远端不是默认本地替代方案。
4. **建立独立工作目录。** 从一致的本地主分支创建`task/<迭代标识>-<任务标识>-<简短英文描述>`，worktree在主仓库旁的`<项目名>-worktrees/<同名主体>/`，省去`task/`前缀；例如`task/003-t02-login`与`003-t02-login/`。沿用原任务标识，检查合法性、唯一性、真实路径与归属，再用`git worktree add -b <分支> <目录> <本地主分支>`并回读HEAD、分支与登记。主目录继续维护主分支，实施和测试进入任务目录。恢复同一任务复用原目录，不把一次修复、审查或重验当新任务；普通修复保留原分支。目录隔离不代表端口、进程、数据库或权限隔离，忽略的本地Skills、配置和依赖须按实际授权准备，不能假定Git会复制它们。

### WIP保存、替代与恢复

需要用户决策的必要阻塞，或用户明确暂停/切换（包括“今天到这里”）时：停止后续实施 → 核对归属、允许保存内容与暂存区 → 精选并创建本地WIP → 远端和推送权限明确时推送对应任务分支并核对远端提交 → 主Agent沿原tasks/verification记录断点、未完成项、原验收状态和恢复条件。记录自身需要入库的改动与任务内容一起核对保存；报告最终提交位置，不为填入提交号无限递归提交记录。没有新改动不造空提交。记录待补的情况保留本地保存事实，不称完整暂停成功。

暂存是组织提交，不能代表独立存档。用具体路径选择内容并读`git diff --cached`；若有其他任务已暂存内容，先按其归属处理或在保留文件内容的前提下移出本次暂存，再提交精选任务内容，不用`git add .`混收。敏感数据、未获准内容和归属不明内容不入库；本地提交不等于远端备份。推送失败保留本地提交并报告“本地已保存、远端未备份”；远端/权限缺失或结果未知分别报告，不伪称成功。

未解决Merge冲突需要用户决策时，保留任务worktree的冲突、MERGE_HEAD和已处理部分，暂停该目录写入；不普通WIP、不自动abort、移除或用于其他任务。可在已有授权内解决的普通技术问题仍在原任务调试，不把每个报错都当决策阻塞。

新方案明确替代旧方案时，关闭已有旧PR并注明替代关系，实际关闭权限仍须适用；关闭不等于删除。按普通起步从同步后主分支另建同任务分支/目录，名称同步加`-r2`、`-r3`，记录替代依据。旧分支、WIP和目录保留到替代方案必要验证、用户验收、收尾及合入，核对确已无需保留后再清理；不把旧分支并入新PR。恢复先回读实际Git、文件和记录，仅补剩余获准动作，不凭旧记录重放。

### 最终集成与自动收尾

用户明确验收对应成果，仓库、远端、目标主分支和执行权限明确时，主Agent连续执行同范围规格/记录收尾、精选提交推送、更新同一PR、最终检查、Squash及清理，正常路径不逐步询问。“继续检查”、AI通过和PR存在都不代替验收。未知目标、必要检查失败/未执行、必须修复项未关闭时不合入；缺工具保留实际缺口。

准备最终集成时fetch并核对当时主线；普通任务尚未包含主线更新时，先妥善保存当前改动，在其worktree以普通`git merge <已获取主线引用>`同步，保留过程提交，不默认Rebase，不重复合并已有更新。补衔接、规格/记录一致性及受影响检查；只文档收尾补一致性，行为变化须重新验证和验收受影响成果。最终内容和证据满足门槛才通过平台把PR Squash合入指定主分支，每任务一条完整正式提交；摘要为`类型(范围): 中文成果摘要`，范围可省略，正文按需说明原因和任务。过程WIP、修复及收尾留在任务分支，不预先改写开发历史。独立代码审查的新判断与旧测试证据是否仍适用分别核对。

核对平台PR实际merged状态、目标主分支、合入提交和交付内容；Squash后任务HEAD通常不是主线祖先，不能只凭`git branch --merged`或祖先检查决定清理。强制推送、改写主线历史、丢弃无关改动、修改保护规则与生产部署不在本自动权限内；合并若触发上线仍核对适用部署授权。

### 清理与操作报告

PR实际合入、验收及记录收尾满足后，确认相关Agent不再使用目录、停止本任务独占进程；核对对应worktree真实归属、暂存/未暂存、未跟踪及被忽略文件。`git status`干净不代表无需保留资料，必要时用`git ls-files --others --ignored --exclude-standard`查忽略资料；需保留的证据、配置、数据和发布产物按既定归属保存并核验。仍在使用、资料未保存、冲突或旧方案保留条件未满足则保留现场。

条件满足，从主目录用`git worktree remove <对应任务目录>`移除目录与登记，成功后才清理对应本地与远端任务分支；Squash不满足普通安全删除祖先条件时，先基于已核对PR/内容确认该具体分支可以删除，再执行仅该分支的删除，不凭失败直接强删。远端已自动删除只核对，不重复删除。保留主目录、其他任务目录及发布标签和必要产物，不移除整个worktrees父目录，不强制绕过worktree保护。清理复用有效证据，不为移目录重跑全量测试或做无关扫描。

每组操作完成或受阻停止后，简述项目/任务、实际动作、提交/PR/分支和剩余事项；提交、推送、合入、目录移除及两端分支删除分别核对报告，未知不算成功。重复请求先查实际仓库、必要远端/PR和记录；已完成告知结果，部分完成只接续获准剩余步骤，有新改动重新核对范围。断点沿tasks/verification，发布沿releases，不另建状态或Git报告树。
