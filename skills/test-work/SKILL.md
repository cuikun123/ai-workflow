# 测试与验证

依据需求、验收和实际影响选择必要检查，使用真实可用的项目工具补充并执行测试，返回覆盖范围、结果和未验证项。用中文说明；来源和完整许可见 [NOTICE.md](NOTICE.md)。

## 专项能力协调

从 execute-task、build-foundation、release-work 或 handle-incident 接收检查时，核对同一项目/成果、请求模式、目标内容/运行版本、原始要求与确认、允许读写及副作用、已有证据、未决项和返回位置。原主 Agent 统一记录、决定修复接续、独立审查和用户验收；本项不再启动 execute-task 或自动部署。真实可用能力先读完整说明，缺能力给材料，不临时安装或伪称调用。

地基检查证明所需真实组件连通；发布检查分别证明候选产物与目标环境的实际结果；线上复现遵守已明确的调查和访问范围。按风险检查权限/敏感数据、非法输入、依赖边界、失败后数据状态及必要恢复。健康响应、模拟演练、静态阅读和真实业务检查分别记，不把代码回退等同数据恢复。适用证据复用一次，环境或内容变化后只补受影响部分。

## 1. 核对范围与角色

读取项目 AGENTS.md、已有导航、用户请求、适用规格与质量/工程约定，关联当前任务、范围、设计和已有验证，再核对实际改动、调用方与测试入口。没有适用迭代但目标明确时直接检查并在对话交付，不创建迭代、导航或平行报告。框架开发资料和业务模板不作为真实业务目标。

| 请求或角色 | 操作范围 |
| --- | --- |
| 仅运行已有测试、只报告或明确不修改 | 按请求执行已有检查，报告覆盖缺口；不增补用例、不改业务、工具、配置或正式记录。检查本身的产物仍须在允许范围。 |
| 增补测试或验证当前功能 | 在请求及已有授权内维护必要测试、测试辅助和隔离数据；真实业务实现的修复另核对适用授权，不因发现问题直接修改。 |
| execute-task 内调用 | 接收当前任务、要求、读写边界和已有证据；本项负责测试方法，原主 Agent 管正式记录、调试安排、独立审查和验收。 |
| 受委派的测试者 | 按指定范围检查，返回实际用例、结果、产物与缺项；不再委派、不更新正式状态。 |

资料可查就先补查；关键业务预期不明时澄清该部分，独立可做的检查继续。不能把现有实现、未确认建议或测试当前期待值当成用户要求，也不为测试补齐不相关的整套文档。

确定预期时区分当前有效规格、本轮变更和具体确认。明确获准的变更只对对应行为和目标版本按 scope 与确认依据检查，其余有效规则继续遵守，草案不能覆盖确认。核对本次是候选实现还是旧版本环境，不能把候选的新要求直接套到旧版本，也不能只因规格尚未同步就要求候选退回旧行为。两份适用确认真正冲突时先澄清受影响部分；流程内接收的摘要也要回看原始依据。独立测试只报告规格待同步及交接需要，不自行改规格；测试通过不触发验收后的同步。

## 2. 选择能证明要求的检查

检查对应实际候选提交与工作目录，核对HEAD、未提交差异、当前环境及产物版本；Git提交存在不证明测试通过，工作区测试也不自动覆盖同名提交。最终候选以真实产品效果验证、全新独立代码审查为主体，必要自动化测试提供支撑；Web成果实际查看网页、截图并操作关键流程，接口/工程/文档使用对应实际入口，不把静态阅读或模拟冒充真实体验。代码审查由主Agent组织，不由测试替代。WIP只保存断点，不算最终交付或验收。

主线普通Merge同步、候选修复或验收后收尾改变内容时，核对原证据适用性，只补受影响检查；文档收尾查相关规格与记录一致性，行为变化交主Agent重新验收受影响成果。PR合入前仍须必要检查真实通过、必修项关闭及最终主线衔接；不为移除worktree机械重跑完整测试。线上补丁检查对应实际运行版本及必要修复，不把main未发布新行为强加到旧线上基线。

先说明本次要验证的行为、关键失败方式和必要层次。可用简短的“要求 → 检查 → 工具/真实依赖 → 预期”对应关系，沿用现有计划，不另建测试策略文件。按影响选择，既不机械执行所有类型，也不以大量容易通过的单元用例替代关键集成。

| 类型 | 适用目标与证据边界 |
| --- | --- |
| 单元 | 检查函数或组件的逻辑、边界、分支与副作用；依赖替身存在时说明真实覆盖到哪一层。 |
| 接口 | 检查请求、响应、状态码、错误、权限和状态变化中适用的契约；注明直接调用处理函数还是真实HTTP等传输。真实传输加实际依赖可同时构成集成检查，不重复计数。 |
| 集成 | 检查实际组件的连接、配置、数据读写、事务或重启恢复等适用要求。需要真实数据库的结论不能只用内存替身证明。 |
| 端到端 | 从声明的用户入口走到结果；Web关键流程按需要用真实浏览器操作，检查可见结果、必要持久化与失败表现。只调用API不能记作浏览器流程通过。 |
| 专项 | 性能、安全、可访问性或兼容检查按项目目标与风险安排；需要独立工具或环境时先核对，不默认开展整套专项审计。 |

选择能定位错误的最小层次，同时保留关键跨边界行为的验证。页面、接口或存储变化需检查相关联路径；只改局部计算且没有跨组件影响时，不必启动整套浏览器和数据库。测试类型有交叉，同一检查说明实际覆盖范围即可。

## 3. 准备真实可运行的条件

查实命令、工作目录、工具版本、测试发现规则和实际配置，核对所需服务、数据、浏览器及凭据。已有命令能满足目标时优先复用；先读脚本副作用，避免测试指向真实业务环境。按已有授权准备已声明的本地依赖；新依赖、重要环境/数据/成本变化先按项目规则处理，不临时换技术栈或修改CI。

测试数据、数据库、账号、端口和文件互相隔离，使用允许的环境与输出位置。记录自己启动或创建了什么，并用测试清理或 finally 关闭连接、服务与浏览器；只清理归属明确的本次产物，保留用户数据。测试工具的截图、追踪等实际产物沿用项目配置或隔离临时目录，记录引用，不额外建立正式报告树。敏感内容只保留必要、可脱敏的证据。

缺少必要工具或环境时，继续独立可运行的检查，列出阻塞原因与补齐条件。替身、静态阅读或模拟仅按实际范围报告，不能冒充真实集成。工具可执行不代表目标环境和操作已经授权。

## 4. 编写能抓住错误的用例

- **从要求独立得到预期。** 使用可核对的字面量或人工检查过的数据；不要让被测函数或同一套辅助逻辑同时计算实际值和预期值。
- **说明要抓住的错误。** 检查正常行为、关键边界和失败后的状态。断言应能揭示错分支、错参数、遗漏写入、错误权限或边界处理；仅匹配源码字符串、常量或私有结构不能证明业务行为。
- **保留真实被测对象。** 理解依赖的副作用再决定替身边界；可以隔离外部或慢依赖，但保留测试要证明的真实行为。调用次数、参数和顺序若是契约，可检查它们；不要只证明替身本身存在。
- **让失败可定位。** 用例独立、数据可重复，必要时控制时钟或等待真实条件；保留超时。需要验证防抖或节流等真实时间语义时按该要求设计，不靠盲目延长等待消除失败。
- **核对测试是否有效。** 修复缺陷时优先复现原失败，再重验；对既有正确行为补测试可能立即通过，不人为制造失败或删除实现。确需验证断言灵敏度时，可在授权的隔离副本做针对性错误变体，不能改坏真实项目来凑红灯。项目已有TDD约定适用时遵守。

测试代码与辅助遵循项目现有组织，不给每个技术步骤另建验收任务，也不为了测试给业务类添加无业务意义的接口。更改原断言前回看规格，不能为了通过调整业务预期。

## 5. 执行并核对结果

实际运行选定的必要检查，读取真实退出码、断言失败、执行/跳过数量、环境错误和关键产物。命令成功但零测试、全跳过、错误过滤或跑错目录，不能证明目标通过。父子测试汇总会重复计数时区分原始输出和实际用例，避免混算。

先运行能发现当前问题的检查，再按影响做回归与必要整合检查。当前内容和环境未变、证据仍适用时复用已有结果；改变了实现、用例或环境后重新核对受影响结论。完整项目命令若运行，报告所有发现的失败；范围外问题单列，不能隐藏，也不自动扩大修复。

区分业务缺陷、测试本身错误、工具调用错误和环境不足。测试错误可在既有测试修改授权内纠正，保留实际经过；必要检查受阻不能把实施或整体状态推成完成。偶发失败先保留首次证据并调查，不用反复重跑直到偶然成功覆盖问题。

## 6. 失败接续与交付

业务失败给出输入、预期、实际、影响和最小复现；同一根因在多个层次暴露时合并解释，并保留各层结果。仅测试的请求返回发现和建议；当前任务有适用修复授权时，主 Agent 可使用已安装 debug-issue 调查修复，再核对原失败及受影响检查。没有该技能时仍可用实际工具调查，但不得声称已调用或临时安装另一套框架。

在 execute-task 内调用时返回该任务；由 build-foundation、release-work、handle-incident 或其他主流程调用时，返回实际调用方，不转入新的 execute-task。原主 Agent 按本次请求范围组织必要独立审查、有效问题修复复查与用户验收；可使用已安装 review-work，避免重复全量审查。测试通过不代替独立审查、用户验收或发布授权，本项不自动开始下一任务。

返回简短总体结论与下列证据：

1. 本次要求、检查范围和未覆盖行为，以及选择这些层次的理由。
2. 实际工具、工作目录、命令、退出结果、用例与跳过数量；说明真实依赖、替身及产物位置。
3. 按层次区分通过、失败、未执行、不适用，后两者给原因；列出必须处理的问题、限制和下一步。
4. 实际改动及修复是否在授权内，已有证据是否仍适用；交付可复验的命令或操作方式。

主 Agent 在允许写入且有适用迭代时，把必要证据合并到 verification.md，实际进度写入 tasks.md；写前回读，保留并发修改、历史检查与用户验收。被委派者只返回结果；没有适用迭代或请求只读时在对话交付。本版不写 state.yaml、不定义全框架状态协议，不执行Git自动操作。Skill提供方法和边界，实际能力取决于宿主工具与项目环境，不构成权限沙箱。
