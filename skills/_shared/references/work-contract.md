# 工作依据与验收契约

本文件是各技能的共同依据。涉及需求、候选、检查、审查或验收时读取；同一轮内容不变可以复用。维护或退役规则时读[来源与归属](rules.json)，来源编号用于维护，不是用户批准。

## 每任务最新地基

任务开始或恢复前，通过context inspect取得实际安装公共规则、项目AGENTS和全部foundation原文，核对已确认且适用的约束与红线。合法空文件不等于地基完整，当前不适用与待补须按阶段说明。

每个任务使用自己的最新context_bind依据；同一会话、另一Agent的记忆、T1的绑定或guard fresh均不能替代T2的committed绑定。地基或tasks全表定义变了，重新读取并核对影响/确认；方法见[state-runtime](state-runtime.md#每任务读取与绑定)。impact/reason由工具在verification同次写入，不先手改记录解锁，也不自动取消历史验收。

语义判断、真实实施和审查仍核对约束是否遵守。绑定观察不作为产品检查通过，接收审查结果及验收前重核当前摘要和候选；独立上下文各自取得当前原文。

## 同一组依据

分清当前有效规格、本轮拟改内容和真实具体确认。获准变化只用于对应候选及目标版本，其余规则继续适用；草案、建议和备注不覆盖确认。候选与旧环境分别核对，不用候选的新要求判旧版本，也不用尚未同步的旧规格否定获准变化。

需求和场景沿用已有稳定ID。确需新增时在当前项目声明唯一ID；不改已有编号，不复用已移除身份。范围、任务、场景、检查及交付用同一组引用，实际内容变化须重核对受影响证据。

## 具体确认

从真实用户消息和项目资料核对已经获得的批准。已有适用授权直接推进普通步骤；“继续”、查询、整理、空回复或AI检查不自动批准未展示方案或成果。

范围、设计、计划可以一并准备和展示；同一次明确确认确实覆盖多个对象时可记录各自引用。字段补齐不是新批准：复用原指令先核对它是否覆盖当前内容，不把旧验收改绑新增业务变化。实际确认冲突或关键范围、数据、安全、成本及交付安排改变时，只澄清受影响部分。

## 工具操作的执行范围

受控宿主使用共享工具门槛时，任务通过 guard_policy 声明实际工作目录、仓库、任务分支、文件范围和工程命令。声明由计划确认覆盖；写入与命令请求使用当次 revision、context snapshot 和任务定义摘要。字段与语义登记方法见[工程执行范围与操作授权](spec-runtime.md#工程执行范围与操作授权)。

普通工具不能直接改状态、框架资源、有效规格或机器记录。已选任务的范围、设计和任务正文修订沿原语义流程处理；普通说明的修改保留原记录块。待验收时保持等待；明确反馈的 task.repair 操作授权才能通过语义流程重新进入验证。验收后的说明补充只使用任务声明的 closeout_paths，并重核验收与候选证据。

无任务的规划正文、登记 JSON 和独立非业务文案由受控宿主观察当前明确请求、准确路径与前像。不把准备文件当作已经登记、批准或启动。检查返回 deny 或 unknown 时，保留原操作，补齐报告的前置后重新检查；allow 也须在实际执行前重新核对当次参数和事实。

## 证据与验收

实施、实际检查、独立审查与用户验收分别记录。检查依据规格和风险选择，读取真实命令、退出码、有效数量与必要输出；不删断言、编造数量或把未运行说成通过。内容不变且证据适用时复用，变化后只补受影响检查。

自查、多视角讨论与真实独立上下文分开。独立审查者读取原要求、可定位候选、必要调用方及证据，不传开发推理。有效必须修复项及影响必要判断的未知未闭环时保持未完成；建议和误报不自动扩大需求。

验证深度按[当前请求与流程选择](routing.md)判断；simplified仅用于明确低影响非业务内容，普通功能及PR独立审查保持。提交成果后保留本任务等待，明确验收后再核对收尾与下一任务前置。简短提供“操作、能看到的结果、实际检查或待确认项”，不把已通过检查重新交用户手工跑。

## 规格随交付更新

只同步已经交付、明确验收且必要检查与审查适用的变化，保留其他任务、未变规则、用户修改和历史。新v2任务使用spec check/spec sync及工具生成收据，方法见[规格与记录工具](spec-runtime.md)；不手改规格或伪填synced替代工具。foundation约定按其独立确认和落实时点维护。

恢复先核对实际文件、原验收对象及已提交操作，只接续未完成部分。同步冲突保留验收事实和当前文件；收尾未满足就不把任务记为全部完成。
