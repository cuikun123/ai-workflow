# 框架开发路线

当前已建立设计与模板骨架，原则与职责确认至D65。十一项两文件Skill源码已写入，D64非Git生命周期融合及D65协调修复、文档职责补齐的实际检查和验收状态见[当前交接](handoff.md)与[框架验证](../tests/README.md)。完整接入、安装器与通用状态运行时尚未实现；具体行为以[决策记录](decisions.md)和对应设计为准。

## 开源能力吸收与适配

当前阶段按已确认能力选择具体上游文件与固定版本，核对完整依赖、许可证与署名、脚本副作用及运行条件；明确保留和改造内容、文档归属、验证方法与维护方式。

已确认的 Superpowers 首次引导及反馈澄清方向直接沿用；D55 融合任务计划，D56 融合执行、协作与证据核对，D57 按方案 A 融合审查与反馈核验，D59 融合调试，D60 融合统一测试，D61 融合需求澄清与方案设计，所选主说明和模板的方法已进入对应 Skill。其他候选的取用按实际缺口评估。产物进入既定框架结构，不要求业务项目临时拼接其他框架。详见 [能力适配设计](design/capability-reuse.md)。

## Git 工作约定

全部Git讨论、来源适配与验证按D63留在独立专题，详见[Git设计](design/git-workflow.md)。D64、D65的非Git能力实施不包含Git策略或写操作；进入该专题后按用户选定范围讨论和确认。

## 框架实现

相应设计与授权具备后，实现最小可用主线：

- 可调用的入口、阶段与专项能力，衔接任务、确认、审查、验证和正式记录。
- 完整能力包组装、安装、资源定位、版本与受管理文件清单，以及初始化检查、重跑保护、失败恢复和用户主动升级。
- 必要状态与数据契约、兼容迁移、依赖声明和实际使用说明。
- 经过适配并可验证的上游方法与资源。

具体实现语言、脚本接口、字段、资源布局及安装分发方式在对应实现前确定，不把字段未定当成重新讨论既有原则的理由。

## 验证与分发

先验证框架工具的确定性行为与实际 AI 场景，再用一个真实的新 Web 项目验证接入、地基、一轮迭代、暂停恢复、发布及异常处理，并覆盖首版交付的升级能力。

业务项目、技术栈和部署环境尚未选择；Java、React、MySQL 是首个验证方向，不是所有项目的固定选型。正式名称、框架许可证及长期分发方式在对应发布前确定；独立 CLI 和更多宿主的演进以后续需要及验证结果为依据。

结构检查、运行验证、用户验收分别记录，未执行的检查如实标注。验证范围见 [tests/README.md](../tests/README.md)，模板保持 [既定空文件策略](../templates/README.md)。
