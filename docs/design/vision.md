# 目标与范围

建立符合个人习惯的 AI 开发框架，兼顾个人与工作场景；优先吸收成熟开源方法，保留自己的流程、文档结构与技术选择。

## 开发者与 AI 的分工

| 开发者 | AI |
| --- | --- |
| 提出目标、问题和业务预期 | 主动调查可复用方案，比较语言与技术路线 |
| 提供已有偏好，决定关键取舍 | 纳入偏好，解释推荐、代价和限制 |
| 逐任务验收成果 | 在已有目标和授权内推进实现与必要检查 |

开发者无需先决定技术细节；没有偏好时，AI 仍负责提供有依据的建议。具体推进方式见[开发流程](workflow.md)。

## 首版范围

- **工具**：聚焦 Codex。
- **项目**：从零建立个人 Web 项目，覆盖地基、小迭代、发布和后续维护。
- **技术**：核心流程不绑定技术栈，可选 profile 提供建议。
- **协作**：主 Agent 统筹，按需分工；关键范围和取舍由用户确认。

Java、React、MySQL 是熟悉的首个验证方向。具体框架、版本、ORM、构建、认证和部署尚未选定，也不是所有项目的默认答案。

## 当前不做

- 接手既有业务项目开发新功能：用户计划另做框架。
- 首版适配所有编码工具和移动端。
- 重写所有成熟方法，或把上游框架原样串联。
- 预置没有业务依据的登录、支付或多租户功能。

## 仓库分工与实际状态

| 仓库 | 保存什么 |
| --- | --- |
| 框架仓库 | 通用方法、模板、工具和来源记录 |
| 业务项目 | 真实代码、需求、当前约定、迭代历史与项目状态 |

验证项目的技术栈不决定框架自身实现语言。方法实现及验证见[当前交接](../handoff.md)；名称、整体许可证、完整接入和分发等待定事项见[决策记录](../decisions.md)。
