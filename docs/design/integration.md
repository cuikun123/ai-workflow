# 接入设计

本页说明框架怎么**装进业务项目**、装完怎么**诊断与恢复**、**版本怎么升级**、**客户端怎么接入**、**构建怎么维护**。给维护框架的人和需要核对依据的 AI 读；使用者装框架看[快速开始](../quickstart.md)，日常开发看[使用指南](../usage.md)。

## 环境与分发

运行工具用 Node.js 24 和 JavaScript ESM，依赖由锁文件固定。分发包含运行工具、技能、模板、schema、来源许可和用户文档（进包清单见[多客户端与用户包设计草案](#多客户端与用户包设计草案)的“分发白名单”）；安装时用户文档进 `.ai-workflow/`、技能进 `.agents/skills/`，`resource-manifest.json` 记包身份和文件摘要用于核对完整性（摘要不等于来源签名）。模型和账户用宿主现有配置，框架不自建模型服务；名称 Iterlane，包名和命令 `iterlane`，MIT 与第三方许可随包保留。

<a id="项目安装布局"></a>

## 项目布局与初始化

项目内业务文档结构见[文档管理](documents.md)；这里只说框架资源落点：`AGENTS.md` 做导航，`.agents/skills/<name>/` 放技能与 NOTICE，`.ai-workflow/` 放运行库、清单、schema 和恢复元数据。业务资料由业务流程维护，不属于资源 repair 可覆盖的文件。

`init` 要点：

1. 装到**已存在的新空目录**。先 `--preview` 列出将要创建的文件、AGENTS 区块变化和冲突（零写），确认后再正式执行。
2. 正式初始化从已校验的本分发包生成；已有业务文件、已有 state 或版本不符时返回冲突，不自动认出、合并或重置。
3. 同版本完整重跑返回 unchanged；缺失框架资源用 `--repair` 只补缺失，不覆盖被改的资源；不同版本一律停止，升级不通过 init 隐式完成。
4. 生成业务骨架、`AGENTS.md` 管理区块、`.gitignore` 忽略区块，以及初始 `state`（revision=0、澄清阶段、无任务），生成后回读校验。
5. `AGENTS.md` 只管理唯一一段 `<!-- ai-workflow:begin -->` 至 `<!-- ai-workflow:end -->` 区块，区块外原字节保留；重复、嵌套或损伤标记时停止。命令、参数和退出码见[命令参考](../../scripts/README.md)。

初始化只做“继续 / 有限还原”，不含通用状态转换、升级或回退；锁只约束本框架工具，外部编辑仍可能竞争，不宣称强隔离。

## 诊断与受控恢复

`doctor` 只读，报告安装/资源/版本、状态/文档、日志/锁、环境/路径、客户端几类问题，给出稳定分类、影响和下一步；不发网络、不写文件、不改状态。成功诊断不等于环境健康或用户验收。

`recover` 一次只选一项动作：

- `--repair --package <包>`：同版本补缺失资源/区块，保留业务资料和改动。
- `--resume` / `--undo --operation-id <id>`：锁定某个安装或状态操作，继续或有限还原。
- `--refresh --expected-revision <n>`：只重绑书签的 basis，不换任务、不代替用户验收。

`--preview` 只读列出目标、替换类别和锁处理，不写锁或文件。原则：保留现场、不猜归属、不按时间挑日志；恢复书签不重试模型、Git、部署或数据库动作，也不新建任务/文档存储。

<a id="框架升级"></a>

## 相邻版本升级与回退

只承诺验证过的**相邻版本**升级与回退（具体支持的版本对见[版本与支持范围](../releasing.md)），保留业务内容和操作历史。

- **来源核对**：包身份同时绑定版本和资源清单摘要，同版本不同来源拒绝混用；未知安装、旧手动副本、未登记版本或不兼容数据明确阻断，不按版本号猜迁移。
- **入口**：用**目标（新）版本**完整包执行 `upgrade`/`rollback`，并显式指定**来源（旧）**完整包；旧入口保持原版本，不伪装成拥有新命令。
- **前置与锁**：项目清单、资源归属、状态/记录、当前 revision 与来源相符；有未完成安装/状态/版本操作、未知日志或锁时阻断；默认当前任务验收收尾后才升级。
- **跨版本日志**：安装、状态、版本各用独立日志；把旧日志按操作归属留在受控本地历史里、原字节不改；回退由固定新工具核验还原。
- **写入与失败**：计划 → 加锁 → 写严格日志和前后像 → 替换资源 → 更新清单 → 提交，每步回读核对；失败或中断保留现场，用匹配工具 `resume`/`undo` 有限恢复，不重写 state/revision、不改业务内容。

这是可检测的多文件协议，不宣称跨目录瞬时原子切换或断电绝对恢复；完整备份不等于用户验收或发布授权。命令与参数见[命令参考](../../scripts/README.md)。

<a id="第0步恢复边界"></a>

## 恢复边界

写入加锁、前后像、可恢复语义和“哪些能救、哪些必须停”的完整协议，见[状态、记录与写入契约：记录与写入保护](state-contract.md#记录与写入保护)。本页只补**接入、版本**这两类操作怎么处理：

| 情况 | 处理 |
| --- | --- |
| 同版本初始化中断 | 按操作日志继续或有限还原；未知文件不自动认领 |
| 升级中断 | 有日志和完整旧资源时恢复一致版本 |
| Git 冲突、提交推送、部署、数据库 | 沿既有 Git/发布规则，recover 不执行 reset、重推或数据库恢复 |

## 规格与验证记录

- `spec check` 只读核对格式、身份、生命周期和 delta/任务/场景引用；`spec sync` 把单任务已验收增量同步进规格（preview 零写，执行返回 operation id 与 sync 记录）。
- state 仍 v1，业务记录与语义日志支持 v1/v2；sync 作为语义动作走同一套日志、锁和恢复，不改旧定义含义。命令与错误码见[命令参考](../../scripts/README.md)。

## Git 行尾保护

项目 `.gitattributes` 的管理区块为指定框架、状态和依据路径关闭文本转换，区块外原文保留；不改全局 Git 设置，不修改 Git 索引或配置。

## 多客户端与用户包设计草案

> 本节是设计草案，不是运行保证。

目标是让不同客户端自动进入同一套框架方法，每个新任务、恢复任务和审查都核对最新项目约定；同时使用者拿到的工具包、ZIP 和安装目录**不夹带维护资料**。做法是共享入口 + 确定性依据校验 + 可用的原生事件适配，不新增模型代理、后台进程或跨客户端调度；它能拒绝不满足依据条件的框架操作，但不认证模型真的理解了规则、也挡不住全部外部编辑。

| 首批客户端 | 接入方式 |
| --- | --- |
| Codex CLI | 项目 `AGENTS.md` 与现有技能入口；运行时拒绝旧绑定 |
| Claude Code | `CLAUDE.md` 管理区块导入 `AGENTS.md`，配合项目 hooks |
| Pi CLI/TUI | 项目 `AGENTS.md` 与项目扩展，提供上下文注入和工具调用核对 |

只验证上述具体产品形态；其他 IDE、云 Agent、SDK 等不随此宣称支持。支持范围见[版本与支持范围](../releasing.md)与[验证记录](../../tests/README.md)；只读问题或独立小修改无需建任务或绑定。

**使用者分发白名单**（什么进用户包、什么只在框架仓库）：

| 内容 | 是否进用户包 |
| --- | --- |
| 包 README、用户文档导航、quickstart、usage、技能索引、命令参考、版本与支持说明、安全反馈 | 进 |
| 运行代码、技能入口与方法、共享规则、必要模板和 schema | 进（运行必需） |
| LICENSE、第三方许可与署名、必要来源标识 | 进（保留完整许可） |
| 收藏示例及其说明 | 进（不含真实业务批准） |
| `docs/design`、decisions、handoff、roadmap、tests/README、CONTRIBUTING、框架仓库 AGENTS | **不进**（只在框架仓库） |

原生事件适配核对共享判定，不自行批准计划或登记验收。操作参数、前置条件及失败处理见[共享工具门槛设计](tool-guard.md)；现有快照校验保持原含义。

## 构建与技能资源维护

- 构建、`ci`、试用 ZIP 打包的具体命令见[贡献说明](../../CONTRIBUTING.md)；源码入口为 `node bin/iterlane.mjs`，固定旧产物不覆盖。
- 共享规则由 `skills/_shared` 构建进各技能 references 并保存摘要；引入上游前核对来源、版本、许可、依赖和副作用，来源留在 sources 与各 NOTICE。

## 后续设计方向

更多平台、接管旧项目、任意历史迁移、强隔离和多 Agent 编排仍需单独设计与验证。当前能力与限制以使用说明和实际结果为准。
