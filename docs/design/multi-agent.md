# 多 Agent 协作

## 已认可的原则

主 Agent 统筹，根据任务建立调研、设计、开发、审查等子 Agent，不固定全角色常驻。默认最多三个子 Agent 同时运行，作为可调整默认值。

首版不默认递归委派；子 Agent 需要协助时向主 Agent 请求。

审查分工已确认 D51：普通功能任务默认安排一次独立审查，低影响修改可简化，高风险内容按需增加专项视角；整轮交付检查跨任务衔接。执行者负责实现、测试与处理反馈，独立审查者读取原始依据和实际产物，返回有证据的发现并复查修复，主 Agent 统一更新正式状态。已在 execute-task 中提供使用宿主工具的交接与审查方法，统一调度器和强制隔离尚未实现；此项设计确认不要求在普通讨论或文档登记时实际委派。

D70、D71进一步要求每个PR合入前通过AI检查，代码规范性检查使用全新的独立上下文Agent；交接只含需求与相关修改、新增，不传开发对话及实现推理，审查者可自行只读项目规范、必要调用方与依赖代码。反馈沿D51先核验再有效修复、重验和独立复查，主Agent统一正式记录；完整并行开发调度仍按D66后置，现有方法不代表新门槛或工具接入已实施、验证。

D72明确审查者先筛选必要问题，主Agent核验后安排原执行者修复并独立复查；非必要意见不驱动本轮修改，也不逐轮交回用户。复查聚焦原问题与修复影响，新增修复项仍需必要性与证据，正式结果和记录继续由主Agent统一维护。

## 并行前提

目标、输入、验收与依赖明确，修改范围可隔离，前置依赖已满足。明确文件负责人，避免在同一工作副本同时修改同一文件。

D84已确认使用Git worktree为任务提供独立工作目录，合入后自动清理按D85：主Agent确认相关Agent停止使用和写入、停止本任务独占进程并保护需保留资料，再移除任务worktree和清理分支；仍被使用或需要保留时暂停清理并报告。D86确定任务目录放在主仓库同级的`<项目名>-worktrees/`下面，每任务独立子目录，清理限对应任务目录。D87确定分支与目录共用迭代标识、任务标识和简短英文描述，更换方案另开分支时同步追加替代后缀并关联原任务；多Agent与分支、工作目录的具体分配仍待设计，完整并行调度继续按D66后置。工作文件分目录不等于进程、数据或权限已经隔离，也不表示协作运行能力已实现。

D88已确认主线更新进入任务分支使用普通Merge：准备集成检查时，先保存当前改动并核对版本，将尚未包含的主线更新同步到任务分支，保留已有提交；最终交付到主分支仍按D77使用Squash。同步后重新核对受影响证据，涉及已验收行为变化时重验并重新验收。此项只明确Git同步方式，不表示多Agent调度已实现，也不改变D66的推进顺序。

D89要求需要用户决策的合并冲突保留在原任务worktree，主Agent确保该目录暂停继续写入，不交给其他任务使用或自动清理；保留已完成处理，记录待决定事项和恢复依据，用户答复后核对现场再继续。合并前保存的提交与本地冲突现场分别报告，未解决冲突时不机械创建普通WIP提交；此约定不启动实际并行调度。

D90要求线上修复基于实际线上运行版本创建修复分支和独立worktree，补丁不机械合入最新main的全部更新；main未发布改动继续保留。D91确定先发布补丁并确认线上恢复，再按D92确保主线覆盖修复：已解决则核验记录，能直接合入则由修复分支提PR，实际冲突或不兼容时才增加主线适配分支。该收尾不默认增加一轮开发或额外分支；线上恢复、主线已覆盖且按D93保留固定发布标签及必要产物后才清理。主Agent分别报告线上恢复和主线处理状态，受阻时保留待处理现场。具体修复迭代安排仍待明确，不据此启动并行执行或真实环境操作。

## 委派信息

目标、验收条件、必读资料、可修改范围、依赖、验证要求和阻塞处理。

## 返回信息

完成内容、修改范围、实际验证结果、遗留问题和待决策事项。

结果的正式结构定义尚未实现，不能用完整表单代替事实证据。

## 主 Agent 接收

检查修改与证据，安排必要审查、联调与整体验证，统一更新状态和正式记录。子 Agent 自报完成不等于通过；失败需要分析而非无限重试。

## 多视角讨论

多视角讨论已按 D64 纳入本轮并写入 discuss-design，适配 BMAD 选定方法。按议题选择相关角度、相互质疑并收敛有条件推荐，保留分歧与未知；讨论结论经对应确认才进入已有需求或设计，不默认生成永久会议文档。

单模型角色扮演与独立子 Agent 不等同，讨论与并行执行也不等同。

十一项能力共用项目/成果、请求模式、目标内容或运行版本、原始依据与确认、允许操作、已有证据、未决项和返回位置。原主 Agent 保留正式记录与验收责任，专项只返回方法和结果，不递归启动执行或重复全量审查。默认同 Agent 分视角时透明说明；只有适用协作要求明确需要且工具可用才进行实际委派，讨论不能冒充独立审查。

已按 D56 创建 [execute-task](../../skills/execute-task/SKILL.md)，协作参考按 D58 完整并入其主说明，由主 Agent 根据实际工具完成交接和结果核验；D57 的 [review-work](../../skills/review-work/SKILL.md) 提供专项审查及反馈核验方法，已委派的审查者读取后自己检查，不再次委派。验证范围见 [框架验证](../../tests/README.md)。没有独立调度器、通用结果 schema 校验器或强制隔离，不能把 Skill 规则视为宿主权限保证。
