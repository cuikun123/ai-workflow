# 版本与支持范围

当前版本是 **0.3.0-dev.12**，技能版本 **0.3.3**。这是内部试用版，还没有公开发布。

## 分清三种目录

| 你手里的是 | 在哪里运行命令 | 命令写法 |
| --- | --- | --- |
| 试用 ZIP 解压后的目录 | 解压目录 | `node runtime/bin/iterlane.mjs` |
| 完整工具包（或 tgz 解出的 `package/`） | 工具包目录 | `node bin/iterlane.mjs` |
| 已安装的项目 | 项目根目录 | `node .ai-workflow/bin/iterlane.mjs` |

安装包里有工具、十一项技能、项目模板、使用文档和许可文件。框架自己的设计、交接和测试记录不会装进你的项目。

几个用来核对完整性的文件：

| 文件 | 位置 | 作用 |
| --- | --- | --- |
| `delivery.json`、`SHA256SUMS` | ZIP 所在的交付目录 | 核对 ZIP 本身 |
| `resource-manifest.json` | 工具包内 | 核对工具包里的文件 |
| `.ai-workflow/manifest.json` | 项目内 | 记录这个项目实际装了什么 |

这些摘要只能证明文件没被改动，不能证明文件来自谁。

## 已经支持

- 在 Windows 上安装到全新的空项目，并检查安装结果。
- 管理任务状态，中断后恢复。
- 读取最新的项目约定，并在每个任务开始、检查、交付时核对。
- 验收后同步规格。
- 诊断本地安装问题，并按记录恢复。

验证环境：Windows 11 x64、本地 NTFS 磁盘、PowerShell 5.1、Node.js 24.18.0、Codex CLI 0.169.0。Node.js 版本要求为 `>=24.18.0 <25`。

## 还不支持

- **把框架接入已有代码的项目。** 目前只支持全新的空项目。
- **其他系统和其他 AI 工具。** Claude Code 和 Pi 的自动接入还没做。`doctor --client` 只能检查 Codex。
- **从 dev.11 升级到 dev.12，或回退。** 已经装了旧版本的项目，保持原样，不要用新包的 `init` 覆盖。
- **生产部署。** 框架不会替你部署。部署需要你的项目自己的工具和授权。

早期装过 dev.5 的项目，仍可以用固定的 dev.6 工具包升级到 dev.6，或从 dev.6 回退。这条路径要用 dev.6 工具包，不能用本版本的工具。新用户不涉及这一条。

## 检查能证明什么

- **能证明**：文件、记录和状态彼此一致，没有缺失或被意外改动。
- **不能证明**：确认真的来自你、审查真的是独立做的、检查真的运行过、成果在业务上正确。这些靠 AI 如实记录和你亲自验收。

AI 工具能否连上模型，取决于工具自己的账号和网络，框架不保证。
