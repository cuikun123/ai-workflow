# Iterlane（迭序）

Iterlane 是面向 AI 编码的项目工作流框架。你提出目标、确认关键方案并验收成果，AI 负责调查、规划、实施、检查和项目记录，让每轮开发有明确的目标、结果和下一步。

例如做一个收藏应用，你可以先说“保存标题和地址，刷新后仍保留”。AI 和你明确范围后，完成页面、接口、存储与必要检查，把完整成果交给你体验；你验收通过后，它更新已交付的业务规格并完成适用收尾。

## 一次开发怎样推进

1. **说明目标**：用业务语言提出问题和预期，AI 补查信息、澄清关键未知。
2. **确认方案和任务**：核对范围、取舍、成果及验收方式。
3. **AI 实施并检查**：自主完成内部步骤，执行必要测试和适用审查，处理问题。
4. **你验收成果**：按真实入口体验，明确通过或给出反馈；不通过就在当前任务修复。
5. **AI 收尾**：更新实际交付的规格和记录，完成获准的 Git 收尾后接续工作。

新项目先建立并验收最小可运行工程和基础约定，也就是“项目地基”。错字或排版改动可以直接处理，复杂工作按影响展开设计与验证。

## 当前适用范围

当前为 **0.3.0-dev.12 内部试用候选**。C1用户包隔离、C2最新地基读取已验收；C3任务绑定与上下文减负已实现并通过相应检查，用户验收状态见交接。Claude Code/Pi自动接入与新的升级路径尚未完成。包含十一项技能及安装、状态、上下文绑定、检查、诊断、恢复和规格同步工具。

主要实测 Windows 本地新项目、Node.js 24 和现有 Codex CLI；从源码构建、ZIP安装、首轮开发与换会话步骤见[快速开始](docs/quickstart.md)，具体支持限制见[发布说明](docs/releasing.md)。已有业务项目接管、更多平台、任意历史升级和生产部署仍需另行验证。Git 和部署操作需要项目自身的真实工具及授权。

工具检查本地记录和文件的一致性；检查通过、客户端可用、用户验收和完整项目可用分别判断。实际检查与缺项见[验证记录](tests/README.md)，包身份见[发布说明](docs/releasing.md)。
