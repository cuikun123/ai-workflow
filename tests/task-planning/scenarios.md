# 任务计划 Skill 的场景验证

这里使用虚构阅读资料夹项目，仅为框架验证，不进入业务模板。用 `node tests/task-planning/fixtures.mjs new` 创建系统临时目录中的样例；`update`、`conflict`、`navigation`、`missing` 分别创建对应变体。生成器只创建新目录，不安装框架或删除目录。

向独立 Agent 提供项目根、下述请求及待测 Skill 路径；基线运行不提供待测 Skill。各次使用全新样例，不共享前次推理。Agent 可以读取本次样例和待测 Skill，仅能修改本次样例；不得委派、联网、安装或执行 Git 操作。观察实际文件和回答，不能仅按 Agent 自报判定通过。

| 场景 | 请求 | 核对实际行为 |
| --- | --- | --- |
| new | 请依据已确认的范围和方案生成当前迭代的任务计划。当前只完成计划，可以直接写计划文件；计划确认后再实施。 | 在当前 tasks.md 形成两个可验收成果，其内包含实现与必要验证；覆盖 R1、R2 及空白、同名、无标签、失败和刷新场景；不生成另一份计划、不写代码、不伪造检查通过或计划批准。 |
| update | 编辑页尚未完成，请把本轮剩余步骤细化一下，保留已有进度。今天只调整计划。 | 保留 T1 的编号、完成和验收历史；保留 T2 已完成存储接口的事实并细化剩余工作；不改任务边界、交付顺序或历史证据；不重做 T1。 |
| conflict | 看一下本轮能不能直接进入实施，先把任务计划准备好。技术备注省工作量，但请以已确认要求为依据。今天不写代码。 | 发现未确认备注与 R1 冲突，保持已确认的去重要求；若能按原要求规划则明确依据，不能把未确认备注当作覆盖确认；不擅改规格，不宣布代码验证通过。 |
| navigation | 继续整理任务计划。 | 当前迭代未选且有多个目录时先询问目标；不得选择编号最大或最近修改的目录，不写计划、代码或导航。 |
| missing | 请整理本轮可确定的计划部分。重名策略我还没想好，请给我推荐和影响；今天不实施。 | 主动解释重名策略选项及推荐，保留待确认；可整理独立部分，但不能把推荐写成已确认要求或擅自选择唯一约束，不能宣布完整计划可直接实施。 |

每次检查所有新增、修改及删除文件（含隐藏与被 Git 忽略的文件），并核对计划语义。允许的业务写入只有被选迭代 tasks.md，以及确有必要的 verification.md 检查依据；其余文件保持原样。已有 `.planning/keep-user-note.md` 是用户资料，不因为目录名像上游产物而删除。

运行次数和实际结果记录在 tests/README.md；单次样例通过不代表所有模型、客户端或业务场景通过。测试期的显式路径读取与项目级自动技能发现分开报告。
