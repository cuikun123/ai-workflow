# 验证与记录

本页说明测试怎么跑、覆盖什么、有哪些已知限制，以及长期保留的验证结论。给维护者读：每次运行的具体输出留在自动检查里，这里只讲怎么复核和结论。

## 怎样运行

在仓库根目录先装依赖，再跑检查：

```powershell
npm ci --ignore-scripts --no-audit --no-fund
node scripts/ci.mjs
```

`scripts/ci.mjs` 会串行跑全部自动测试，再构建并打包，结果写到 `.artifacts/`（不进版本库）。默认不调用真实模型。

真实模型评测不随自动检查运行，需要完整的发布包、可用的客户端，并把结果输出到仓库之外的目录；具体做法在维护记录里说明。

> 在 Git Bash 里跑打包相关步骤时，要确保系统自带的 tar 在搜索路径里优先，否则 Windows 盘符路径可能解不开；用 PowerShell 没有这个问题。

## 覆盖什么

- 安装、初始化、诊断与恢复；
- 数据结构与格式、状态书签与任务绑定；
- 写入的一致性、过时判定和中断恢复；
- 相邻版本升级与回退；
- 开发流程、记录与规格同步；
- 技能包的结构、方法内容与来源许可完整性；
- 端到端场景，以及真实客户端会话的驱动逻辑。

工具能拒绝过时绑定、坏记录、冲突和提前收尾，但不能认证模型是否真的理解并遵守约定，也不替代用户验收。

## 已知限制

- 默认串行运行，全套耗时较长，尚未并行化。
- 真实模型验证有费用，不在默认检查里。
- 客户端检查目前只覆盖已有的 Codex 配置，不能据此证明其他客户端可用。
- 其他操作系统、任意历史版本迁移、强隔离和生产环境尚未完整验证。
- 旧的连接错误、限流和重连失败等历史限制如实保留，不当作“全部通过”。

## 长期保留的验证结论

框架的安装与初始化、状态与任务绑定、写入与恢复、相邻版本升级回退、客户端接入、文档完整性等，都已按范围做过实际验证并留有记录；每次运行的具体输出在自动检查的结果里，不在本页复制。

个别旧版本或个别环境下的失败与补验也如实保留在记录中，不用后来的通过覆盖它们；未完成或受限的范围见上面的“已知限制”。
