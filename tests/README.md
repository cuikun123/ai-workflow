# 验证与记录

本页说明测试怎么跑、覆盖什么、有哪些已知限制，以及长期保留的验证结论。给维护者读：每次运行的具体输出留在自动检查里，这里只讲怎么复核和结论。

## 怎样运行

在仓库根目录先装依赖，再跑检查：

```powershell
npm ci --ignore-scripts --no-audit --no-fund
node scripts/ci.mjs
```

`scripts/ci.mjs` 会串行跑全部自动测试，再构建并打包，结果写到 `.artifacts/`（不进版本库）。默认不调用真实模型。

真实模型评测不随自动检查运行，需要完整的发布包、可用的客户端，并把结果输出到仓库之外的目录；具体做法在维护记录里说明。

> 在 Git Bash 里跑打包相关步骤时，要确保系统自带的 tar 在搜索路径里优先，否则 Windows 盘符路径可能解不开；用 PowerShell 没有这个问题。

## 覆盖什么

- 安装、初始化、诊断与恢复；
- 数据结构与格式、状态书签与任务绑定；
- 结构化工具请求、执行范围、操作授权和集成检查上下文；
- 文件前像、路径身份、机器记录保护、实际工程命令和操作前重新判定；
- 实际 Git worktree、分支、索引与远端目标、候选证据和平台观察缺失；
- 命令行和完整工具包接口对相同请求的判定；
- 写入的一致性、过时判定和中断恢复；
- 相邻版本升级与回退；
- 开发流程、记录与规格同步；
- 技能包的结构、方法内容与来源许可完整性；
- 端到端场景，以及真实客户端会话的驱动逻辑。

工具能拒绝过时绑定、坏记录、冲突和提前收尾，但不能认证模型是否真的理解并遵守约定，也不替代用户验收。

## 已知限制

- 默认串行运行，全套耗时较长，尚未并行化。
- 真实模型验证有费用，不在默认检查里。
- 客户端检查目前只覆盖已有的 Codex 配置，不能据此证明其他客户端可用。
- 其他操作系统、任意历史版本迁移、强隔离和生产环境尚未完整验证。
- 安装与恢复的部分用例依赖真实子进程和原生文件锁，满载或较慢的机器上会耗时很久；失败时先单独重跑该文件，分清是等待问题还是实际缺陷。
- 旧的连接错误、限流和重连失败等历史限制如实保留，不当作“全部通过”。

## 长期保留的验证结论

框架的安装与初始化、状态与任务绑定、写入与恢复、相邻版本升级回退、客户端接入、文档完整性等，都已按范围做过实际验证并留有记录；每次运行的具体输出在自动检查的结果里，不在本页复制。

个别旧版本或个别环境下的失败与补验也如实保留在记录中，不用后来的通过覆盖它们；未完成或受限的范围见上面的“已知限制”。

### 原生工具操作的验证依据

维护者需要分别核对框架状态门槛和宿主原生工具的操作结果。Pi 原始会话显示，执行技能及实施方法已被读取。进入实施后，任务仍没有登记、绑定和启动。独立审查由用户提醒后才安排。任务主体在用户验收前已直接推入主分支。

隔离回放使用项目实际安装的框架资源，以及 Pi 的原生文件写入工具和命令执行工具。框架拒绝缺少任务前置的绑定与启动。原生工具仍可写入代码、提交并推送到本地测试远端的主分支。状态保持尚未开始且没有当前任务。回放不访问真实云服务或远端平台，真实项目文件摘要保持不变。

这项依据验证的是工具操作路径，不证明新模型会重复同样的选择。复核时需同时查看原始会话中的技能读取和实际操作、框架拒绝结果，以及隔离项目的文件、状态和本地远端内容。框架操作的核对条件可从[任务绑定实现](../src/context-binding.mjs)和[状态转换实现](../src/workflow-transitions.mjs)追溯；支持范围见[版本与支持范围](../docs/releasing.md)。

### 共享契约的验证依据

维护者可从[请求结构](../schemas/guard-request.schema.json)、[确认与候选检查](../src/workflow-prerequisites.mjs)和[旧结构对照](fixtures/workflow-record-before-guard.schema.json)复核契约边界。

实际检查覆盖请求解析、字节限制、字面参数保留、Unicode 往返、执行范围修订和确认对象匹配。跨任务确认不能互相取代；集成检查上下文不能充当产品检查。固定旧结构的校验接受原记录、拒绝新增字段。前后文件比较验证检查没有写入副作用，原状态与绑定路径也做了回归。

契约验证覆盖结构与共用前置检查。操作判定的依据见[共享操作判定的验证依据](#共享操作判定的验证依据)，支持范围见[版本与支持范围](../docs/releasing.md)。

### 共享操作判定的验证依据

维护者可从[共享判定入口](../src/operation-guard.mjs)、[路径与记录保护](../src/operation-files.mjs)和[实际工具身份检查](../src/operation-command.mjs)复核操作边界。

路径身份按实际目录核对：大小写与 Unicode 别名被拒绝，短名或平台写法差异按同一目录处理并采用实际路径，否则真实主机的短名临时目录会使全部判定失效。

隔离用例使用实际构建并安装的框架资源，以及临时本地仓库。有效确认、绑定、任务阶段和范围允许对应文件修改与工程命令。缺任务、缺确认、过时绑定、等待验收、跨任务及错误前像不能放行。规划正文、登记输入和独立非业务文案使用受控宿主观察；验收后的普通说明须有适用的候选证据。

实际文件检查覆盖链接、路径别名、移动两端和机器记录变化。实际程序检查覆盖字节变化、改名解释器、不同位宽的命令解释器，以及冒用已知工程工具名称的输入。任务声明不能单独证明可执行文件类别。普通正文的容量与原记录文档默认容量分别核对，原状态与确认流程也做了回归。

允许、拒绝、未知、格式错误、宿主观察异常及重新判定均核对前后文件与状态。检查期间变化保留外部修改并拒绝放行。代码审查与文件快照共同核对判定入口的只读行为；被检查的工程命令和语义写入没有由门槛执行。任务、批准和审查前置均明确标为合成输入，不冒充真实用户验收或模型独立审查。

共享 Git 用例检查真实临时仓库、任务分支、索引和本地测试远端。开发保存、未验收推送、直接推主分支和最终集成分别检查。最终集成中的平台事实由测试专用合成观察提供，不表示真实远端平台已接入。源码入口、命令行和完整包模块按相同请求比较判定；安装包损坏会使 guard 模块创建失败。检查不会提交、推送、合入或执行被判定的业务操作。

独立复查核对后的结论如下，维护者可据此复核边界，而不必信任实现描述。

- 伪造入口已关闭：请求中的索引摘要、候选提交、主线提交、远端地址和路径都逐项与实际 Git 事实对齐；进度备份这一自报意图同时受暂停或阻塞状态与断点记录约束；平台事实只从受控调用方读取，命令从不传入，缺失或异常返回未知。
- 陈旧结果不能复用：重新判定会全量重跑并比对请求摘要、读取集合与已观察事实，改变暂存内容或追加未覆盖路径都会被拒。
- 只读边界成立：查询命令是严格白名单，不包含任何写入、拉取、推送或凭据交互；可重定向仓库的环境变量被清除，外部差异程序、文本转换程序和可能写缓存的配置均被关闭；判定前后比对仓库与本地远端，未见写入。
- 主分支跳步已关闭：直接推送主分支固定拒绝，交付只能走集成判定；集成必须同时满足当前验收、规格收尾、覆盖当前主线与候选两端的检查记录，以及受控宿主提供的平台事实；仅获推送授权不能代替验收或审查。

### 交付接口的验证依据

命令行与完整包模块需要与源码入口给出同一判定，且失败时不能降级放行。

维护者可从[命令行入口](../src/cli.mjs)、[完整包模块](../src/guard-runtime.mjs)和[打包清单](../src/package.mjs)复核。验证覆盖：允许、拒绝、未知和格式错误各自对应稳定的退出类别；安装损坏与请求格式错误分开报告；输入文件为符号链接、非普通文件或超出大小上限时在判定前拒绝；命令行不接受平台结果，因此最终集成在命令行走不到允许。

完整包把判定模块与请求、返回结构一并纳入资源清单和摘要核对。同一请求在源码、构建产物和命令行之间比较结果；模块缺失或资源与运行时结构不一致时，包检查失败而不是继续提供判定。

### 真实形态的验证依据

判定 Git 行为的门槛不能只在临时初始化的空仓库上验证。空仓库没有链接工作区、没有属性文件，也不发生换行转换，看起来通过并不代表真实仓库可用。

维护者可从[Git 判定实现](../src/operation-git.mjs)和[只读 Git 查询](../src/git-read.mjs)复核边界。验证覆盖三类真实形态：由 `git worktree` 创建的任务工作目录，其仓库元数据以文件形式指向公共目录；含文本转换规则的属性文件；以及工作区按平台换行输出时与仓库记录内容的比较。外部内容过滤器仍然拒绝，属性文件不能让这类过滤器进入读取路径。

框架仓库自身也做过实际调用：在任务分支的真实工作目录上读取仓库身份、分支和索引摘要，结果与 `git` 命令一致且没有写入。这不等于所有已安装项目都已核对，其他项目形态和平台需按同样方式验证。
