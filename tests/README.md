# 验证与验收

本页记录实际检查结果、已知限制和证据位置。测试通过、客户端可用和用户验收是不同的事实，分别记录。

## 怎样运行测试

在仓库根目录安装依赖后运行：

```powershell
npm ci --ignore-scripts --no-audit --no-fund
node scripts/ci.mjs
```

CI 串行运行全部 79 个测试文件，构建并打包，结果写入 `.artifacts/`。测试不调用真实模型；真实模型评测需要另外指定完整包、客户端和仓库外输出目录：

```powershell
node tests/end-to-end/usability-run.mjs --out <新目录> --package <完整包> --cli <实际CLI>
```

`--resume` 只接续已完整落盘的会话。部分会话和业务文件变化会保留证据并拒绝复用。

**注意**：在 Git Bash 中运行打包测试时，需要把 Windows 自带的 tar 放到 PATH 前面（GNU tar 无法解开 `C:` 路径）。在 PowerShell 中运行没有这个问题。

## 测试覆盖什么

| 目录 | 覆盖内容 |
| --- | --- |
| `tests/runtime/` | 安装、格式、绑定、恢复、版本升级回退、工作流等确定性行为 |
| `tests/codex-client/` | 特定真实 Codex 会话的驱动逻辑与证据识别 |
| `tests/end-to-end/` | 完整安装→发现→路由→查询的场景，以及端到端会话驱动 |
| `tests/*/package.test.mjs` | 技能结构、方法内容和来源许可的完整性 |
| `tests/helpers/`、`tests/fixtures/` | 共用夹具和固定旧版本包 |

工具能拒绝过时绑定、坏记录、冲突和提前收尾，不能认证 AI 是否真正理解和遵守约定，也不替代用户验收。

## 已知限制

- 普通 CI 串行运行，全套约需 1.5–2 小时；并行改造尚未完成。
- 真实模型验证有成本，不在默认 CI 中运行。
- `doctor --client` 只检查已有 Codex 配置，不能用于证明其他客户端可用。
- 旧 EOF、限流及重连失败保留为历史限制；旧模型复验按用户决定跳过。
- 其他平台、任意历史迁移、强隔离、生产和框架远端 CI 未完整验证。
