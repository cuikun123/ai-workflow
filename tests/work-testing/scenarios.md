# test-work 场景验证

`node tests/work-testing/fixtures.mjs <kind> [installed]` 在系统临时目录生成独立虚构书签应用；installed 复制完整 test-work，integration 另复制 execute-task、debug-issue、review-work。project/ 下 .txt 是测试输入模板，复制后才成为源码或测试，不随 Skill 安装，也不加入框架包检查的执行范围。

场景 Agent 只收到临时项目路径、项目 notes/request.md、已有规格/工具和已安装 Skill，不提供缺陷位置、生成器或预期答案。其在项目中承担主测试 Agent（unit-only 明确为受委派角色），允许的正式记录依请求核对；外层框架主 Agent 比较全部文件摘要、阅读实际用例并重跑检查。宿主固有指导仍可能存在，不把基线解释为完全无提示模型。

| 场景 | 要验证的行为 |
| --- | --- |
| coverage，无技能基线及有技能各一次 | 按R1-R4选择检查，补有效测试，分别验证校验、真实HTTP响应及失败后状态、SQLite关闭再开、真实浏览器保存和刷新。发现业务问题保留失败，不在仅测试授权下修复。 |
| report-only | 仅执行已有测试，不创建用例或改正式记录；已有两个测试通过不代表R1-R4完整覆盖。 |
| unit-only | 只验证R1，补必要单元用例；不启动HTTP、数据库或浏览器，不写正式记录，不机械跑所有类型。 |
| blocked | 运行本地用例和明确的固定失败集成入口；记录实际退出结果与未覆盖项，不替换入口、不安装或伪造真实集成。 |
| integration | execute-task 实际使用 test-work，失败后按授权进入 debug-issue，再重验并由真实独立 review-work 审查；保留T2、历史和待用户验收事实。 |

测试工具和副作用：Node v24 的内置 node:test、fetch、node:sqlite；HTTP只监听127.0.0.1随机端口，SQLite和浏览器profile放系统临时目录。browser.mjs 调用已安装Edge或Chrome的无头进程，通过真实CDP页面操作，显式导航并等待实际加载、刷新事件；不使用日常浏览器profile，不安装浏览器。测试须在finally或测试清理中关闭自己创建的服务与浏览器；临时数据库和profile可保留供证据核验，不清理用户目录或其他进程。页面资源全部来自临时本地应用，测试不访问外部业务。

初始用例只覆盖HTTPS规范化与空字符串，允许Agent据原规格补足真实行为检查；根源缺陷可在多个层次暴露，但报告须去重。接口验证是否包含真实数据库要明确，不能将同一检查重复计作多项独立证据。浏览器应实际操作输入与保存并刷新，HTTP请求不能代替UI验证。

本轮后续独立审查另发现 app 模板逐块拼接 Buffer 会破坏跨HTTP块的UTF-8字符。该问题不是最初预设的协议缺陷，原始模板保留为本次实际测试输入；初始 coverage 的37例没有覆盖此条件，不能声称已覆盖R2全部传输情况。联动项目在原任务内补回归、修复并复查，证据另记于验证记录。

模板和工具需先作基础连通检查再发给场景Agent。最终验证记录注明命令、工作目录、各类数量与失败、真实依赖/替身边界、文件差异及未运行事项，不从Skill文字或包检查推导实际能力。详见 ../README.md。
