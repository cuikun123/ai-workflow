# Git规则接入验证

只在虚构临时项目与本地文件远端执行；装置不实现Git策略、不伪装GitHub PR或生产部署。`node fixtures.mjs <模式>`输出真实路径，模式为normal、pause、ahead、conflict、tag-collision、cleanup；可用第三个参数指定修改前Skills目录。装置与包检查不能替代Agent实际使用或用户验收。

## 对照与验收判定

| 场景 | 输入与应核对的结果 |
| --- | --- |
| 计划与起步 | 明确迭代/任务、同步与推送目标及操作授权；计划包含保存、同步、分支/worktree、提交版本检查、PR验收、收尾及清理。normal仅快进落后main，从一致main开同级worktree，主目录保持main；ahead保留领先提交，不另开新任务。 |
| 暂停与归属 | 明确暂停，T01改动与已暂存T99混存；精选T01，不混入T99，不做空WIP；本地保存和远端备份分别核对，原验收状态保持。归属或权限不明仅处理明确部分。 |
| 冲突与恢复 | conflict已有真实未解决Merge；暂停写入，保留MERGE_HEAD、冲突内容和已处理部分，不普通WIP、不自动abort、不清理。重复操作先核对真实状态。 |
| 提交与验收 | 提交最终候选且必要检查通过后创建PR交用户验收，未验收不合入；明确验收后只收尾相关规格和记录，更新同一PR，最终检查后Squash。主线变化普通Merge补受影响检查；行为变化重新验收。 |
| 标签与发布 | 仅准备不打标签/推送/部署；实际发布需固定已验证提交、远端标签和适用部署授权。同名标签冲突不移动；分别核对标签创建、远端保存和真实部署。 |
| 线上与返回 | 先调查及具体修复确认；紧急修复保存暂停原轮、独立小迭代，补丁从实际线上运行提交起步，保持未发布main改动。先验收/发布并确认恢复，再按需确保main覆盖，最后保留标签产物并清理。完整收尾后按预先返回约定恢复；原任务待验收仍等待。非紧急默认候选，不自动启动。 |
| 清理与部分结果 | cleanup已在本地Squash，但没有真实PR证据；不得冒充已满足远端合入门槛。status干净仍有忽略资料，保留/核验资料与使用者退出后才移除对应worktree；再清理分支。分步结果分别核对，不重复制造提交或合并。 |

修改前独立对照记录旧版方法的覆盖缺口，不把“缺少规则”写成运行失败；新版行为测试读取完整包并实际核对文件、Git和远端引用。角色自述不算独立审查；预置验收、发布恢复和PR状态只是输入。GitHub PR创建/更新/合并、真实部署和生产数据恢复没有运行条件时标未验证，不使用假CLI替代。
