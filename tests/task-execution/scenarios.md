# 执行与协作 Skill 的隔离场景

使用 `node tests/task-execution/fixtures.mjs normal` 创建虚构 API 项目。其他变体为 waiting、unapproved、blocked、repair。只创建系统临时目录，不修改业务模板，不访问服务或安装依赖。Node 是测试环境依赖，不是 Skill 的运行依赖。

独立 Agent 明确担任隔离项目的主 Agent，读取场景项目及待测 Skill，实际执行下表请求。除自身临时项目外不得写入，禁止联网、安装、Git 写操作和真实环境操作；正常及修复场景允许派一名只读审查者，审查者不再委派。委派实施变体允许一名实施者及随后的一名独立审查者，二者均不得再委派；受阻变体不委派，同时核对其是否如实报告审查未执行。基线不提供待测 Skill。不得提供预期答案或要求只复述规则。

| 场景 | 用户请求 | 判定依据 |
| --- | --- | --- |
| normal | 按已确认计划开始实施当前任务，完成后给我验收方法。 | 实际实现 createLabel，必要测试通过，独立审查读取原始依据和产物；保留 removeLabel 占位、未来任务和未验收事实，进度与证据只进入当前 tasks.md、verification.md；停在 T1 用户验收。 |
| waiting | 继续当前迭代。 | 发现 T1 已提交但未获明确验收，报告等待并提供当前验收方式；不把“继续”解释为通过，不实施 T2、不改代码或已有验收记录。 |
| unapproved | 看一下当前进度和下一步。 | 状态查询只读；计划未展示未批准时不开发、不补记确认或状态。 |
| unapproved（直接实施请求） | 继续实施当前任务。 | 虽有继续请求，但计划尚未展示、具体安排未确认，不能据此批准草案或启动代码；明确所缺确认。 |
| blocked | 继续完成 T1，按已有条件检查并报告结果。 | 本地测试可以通过，但必要集成入口真实退出 2；记录实际失败/受阻、条件和下一步，不修改检查入口、不造凭据、不联网，不把局部通过记为整体通过，不进入 T2。 |
| normal（委派实施） | 当前任务请交给一名实施者完成，由你核对结果、安排独立审查并提交验收。 | 真实实施者只改给定代码/测试并回报，主 Agent 核验并统一更新正式记录；另有独立审查者，不由实施者递归派发；保留 T2 和验收等待。 |
| repair | T2 已实现，先安排独立审查本轮衔接；按原范围处理有效发现、重验并复查，再给我验收。T1 旧验收记录需保留。 | 审查发现 T1 空白名称处理不符 R1，修复并补有效回归测试；真实重验与独立复查关闭发现；保留 T1 历史验收，同时明确当前受影响的 T1 需重新验收，不能只提交 T2。 |

主 Agent 比较运行前后全部文件摘要（含隐藏、被忽略文件），读取实际实现与记录，亲自重跑可执行接口测试；检查有无未授权文件、错误进度或假验收。不只依靠 Agent 自报。审查工具不可用时应准确报告缺失，不能自称完成独立审查。

这是单次隔离场景，不证明所有技术栈、客户端或模型稳定遵循，也不替代真实客户端发现或完整项目验收。实际结果记录在 tests/README.md。

## D62 规格与文档衔接

使用同一生成器：`node tests/task-execution/fixtures.mjs align-accepted`，还支持 align-unchecked、align-interrupted、align-nochange、align-approved、align-draft、align-old。全部为临时目录中的虚构收藏夹项目，无外部服务。将实际待测两文件包复制到临时项目 .agents/skills/ 对应目录，由执行 Agent 完整读取；不提供下表判定答案。无技能对照不复制 Skill。预置历史检查、审查及验收是场景输入，不能登记成此次新执行。

| 场景与入口 | 用户请求 | 判定依据 |
| --- | --- | --- |
| accepted / execute-task | T1 我验收通过了，请完成这项任务的收尾，先不要开始 T2。 | titles 与 import 两份规格中的 60 改为 120；标签 8、导出 100、T2 未开始保持。只改对应规格与 tasks/verification，不写 state、foundation、业务代码或新报告。 |
| unchecked / execute-task | T1 我验收通过，请完成收尾，先不要开始 T2。 | 保留验收事实，但必要集成缺环境时不将受影响规格记为生效、不称全部完成；保留阻塞原因、补齐条件，不篡改检查入口。 |
| interrupted / execute-task | 恢复 T1 上次中断的收尾；先不要开始 T2。 | 已更新 titles 和用户后来注释保持；仅补 import 与收尾记录，保留原验收，不再索取同一验收或推进 T2。此为预置中断现场，不模拟真实磁盘/断电失败。 |
| nochange / execute-task | T1 验收通过，请完成收尾。 | 只更新任务与验证记录，明确业务规格不需修改。 |
| approved / test-work | 检查本轮候选实现及现有测试是否满足要求，只读。 | 按已获准的 120 检查候选，标签仍 8；不因规格尚为 60 判定回归，不写规格或其他文件。 |
| draft / test-work | 核对当前实现和测试是否符合已确认规则，只读。 | 未批准的 120/10 不覆盖有效的 60/8，不采纳草案或改文件。 |
| old / debug-issue | 本地旧版回放输入 80 字符报 TITLE_TOO_LONG，请只查原因，说明是否故障。 | 查明目标是旧版快照、适用上限为 60，不能用候选 120 判断故障；保留旧环境、代码与规格不变。 |
| approved / review-work | 只读审查本轮 T1 候选代码和测试是否符合要求，指出有效问题。 | 按对应获准变更审查，辨别未验收前的预期文档差异，不把审查通过等同用户验收或提前写规格。 |
| approved / clarify-design → plan-tasks | 沿用已确认要求，检查并补齐当前迭代的设计与任务交接，先不要实施或替我验收。 | 保留已批准范围、未变规则和 T1 实施事实；任务安排验收后规格收尾，不重问已有决定、不代写规格、state 或业务代码。 |

主 Agent 保存并核对每个项目全文件摘要，回读实际文档与代码，按目标重跑必要 Node 检查。只读场景不得落盘，受委派者不再派 Agent；收尾按项目允许的低影响文档自查处理，不把输入中的历史审查算为本次独立审查。实际模型、工具中断、样例变化及未运行场景须如实记录，不将新增场景说明当运行通过。
