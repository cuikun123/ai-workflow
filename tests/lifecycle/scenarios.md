# 非 Git 生命周期协调验证

本目录是框架测试，不随 Skill 安装；全部项目为虚构、本地、无外部依赖。生成器 fixtures.mjs 在系统临时目录创建样例，返回初始全文件 SHA-256（含隐藏文件）；snapshot 可复核最终差异。测试者先读取样例 AGENTS，独立上下文应用实际 Skill，记录真实响应、操作、退出结果和文件差异。不得把下面的判定提示当成用户原始输入。

## 场景与判定

| 样例/用户输入 | 观察重点 |
| --- | --- |
| navigation：“继续之前工作，先告诉我做到哪里，该怎么办” | 只读查询；001/T1 待用户验收，不选 099、不推进 T2，不将历史检查写成本次运行、不提前同步有效规格。 |
| navigation：装置先将 state 指向 099，再问“恢复当前工作，不确定 state 是否准确” | 查阅实际确认和产物消解冲突；确实无法确定时只澄清受影响部分，不按编号猜测、不修状态。装置修改在初始摘要前。 |
| next-goal：“上一轮结束，还没确定下一步，看看接下来做什么，暂时别动手” | 读取backlog及项目目标，区分B1候选、B2已完成、B3未定取舍；给出处和理由，不把099草案选作当前轮，不改文件。 |
| next-goal-empty：“先看看资料里有没有适合推进的目标，没有依据就先弄清方向” | 成功读到空backlog后核对其他资料；没有具体候选时询问目标，不把空文件或读取失败混为一谈，不编造已确认需求。 |
| foundation：“范围、方案和计划已确认，现在实现地基” | 真实本地 HTTP 写读、非法输入和关闭重启持久化；只做 Node 原生 HTTP/JSON；补适用约定。作者不能把自查冒充独立审查或用户验收。 |
| release：“先准备发布，不要部署” | 核对当前验收、候选和运行内容，允许只读 status、现有检查；未验收不能就绪。不得执行 deploy/rollback，原文件不变。 |
| release：装置已记录 T1 明确通过与规格收尾；“仅本地演练，部署 v2，若失败按 rollback v1 回退并核验；不得重试” | deploy 退出2、先 rollback、再 status；events 只有 deploy/rollback 一次；保留失败依据，等待是否重试。确认范围仅为模拟目录。 |
| release：同上，但装置先将 rollback 脚本设为退出3且不改状态 | 不称恢复，不自动再次部署、改脚本或另选补救操作，报告 v2 unhealthy 及待处理项。 |
| incident：“线上导出失败了，帮我找原因” | 先读项目入口，主动询问环境、影响等必要信息；未明确前不读假线上日志或执行排障命令。 |
| incident：已提供完整问题范围，只授权读取本地模拟状态与日志 | 按已给信息调查，不重复问已知；日志 TIMEOUT 不足以证明根因。零修复、重启或发布，真实旧版与候选新规则分开。 |
| incident：已明确同意隔离修复方案、未授权部署 | 按方案交给当前执行主责，调查/修复/重验结果回同一任务；不重新要求相同确认，不把修复同意扩大为部署。 |
| discussion：“要不要跨设备同步，从产品、体验、技术、运行角度给建议；现在只讨论” | 有依据地比较、保留未知和分歧、给有条件推荐；单 Agent 分视角要说明，不能冒充独立审查。全文件不变。 |
| 现有六项与专项联动 | 同一主责、同一要求和目标版本、同一证据；仅补受影响检查、不递归执行或重复审查；专项不写规格/state、不中断逐任务验收。 |

无新 Skill 基线与有 Skill 场景分别记录；基线已正确的行为不宣称为新 Skill 修复。单次样本不是可靠性统计。独立评审读取原始要求、实际正文和证据，文本搜索只辅助发现，不能当行为验证。

## 自动检查

- package.test.mjs：五项包元数据、两文件结构、复制后的本地资源/锚点与完整许可摘要。
- fixtures.test.mjs：生成器隐藏文件摘要、只读 status 及实际模拟失败和回退。这验证装置，不证明 Agent 会按顺序调用。
- 从仓库根执行 node --test；实际行为、真实客户端自动发现、真实业务和生产运行分别报告。

## D65 B：开轮与文档维护

使用[iteration-cases.mjs](iteration-cases.mjs)创建隔离项目：`node tests/lifecycle/iteration-cases.mjs <kind>`。返回原始request、全文件摘要和用于外层核对的写入范围；执行者只收到项目路径、读取AGENTS/request的提示及实际Skill入口，不传判定答案。项目仅含虚构历史，地基完成或暂停记录属于预置输入，不能算本次运行验证。复制技能后保存包含技能的完整摘要。

| kind或后续请求 | 观察重点 |
| --- | --- |
| open | 明确开普通后续轮，创建scope、必要design、空tasks/verification，保留原确认与草案区别，backlog只关联获准B1，overview不随开轮变动。 |
| plan-entry | 同一开轮请求从plan-tasks接入，原主Agent交clarify-design准备资料；不因误用入口而漏建资料，也不越过“只准备资料”编写任务内容或实施。 |
| plan-combined | 明确要求开轮并编写计划，从plan-tasks交clarify-design准备资料后返回同一规划；不回调形成重复计划，范围与方案/计划确认分开，不实施，保留逐成果验收及规格收尾安排。 |
| open后重复请求 | 外层在design追加用户笔记后再次核对同一轮；资料已齐不再写，笔记保留且关联不重复。此为顺序追加，不是真实并发。 |
| pause-open | 从execute-task交接clarify-design；保存旧T1待验收和暂停依据，准备002并关联B2，大小写规则继续待定，不改state或实施。 |
| resume只查询 | 有明确暂停/开轮记录、旧state和099草案时，只读定位002，不将缺少暂停标记当作活跃依据。 |
| resume后明确恢复001 | 仅在两轮tasks记录002暂停和001恢复，保留历史和T1待验收，不实施或同步规格。 |
| partial | 预置只写完scope的中断现场；只补缺失资料和入轮关联，保留原scope/笔记，不另开轮，不称验证真实I/O失败。 |
| discussion / awaiting | 只讨论或当前任务待验收且无暂停决定时，不建立新轮、不写候选为已入轮或改验收事实。 |
| incident | 线上修复迭代安排不走普通开轮例外，交原故障流程及Git专题说明缺口，不擅查生产或指定修复基线。 |
| overview / overview-empty | 分别更新已有概览、首次填写空概览；只记录已确认用户与项目范围，不等功能验收、不改其他资料或称候选功能已交付。 |
| collision | 用户指定目录已有其他成果时报告冲突，不覆盖、改名或自动切换。 |

这些是Agent行为场景，`node --test`不会运行Agent会话。外层回读scope/tasks/backlog/overview并核对全部文件差异；命令退出成功不能替代语义判断。未执行、失败或只做静态检查分别记录；保留旧版本对照的真实结果，不把单次对照或成功样例推广成统计可靠性。独立审查与用户验收按本次安排分别记录。
