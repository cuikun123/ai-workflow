# 项目协作导航（接入模板草案）

此文件提供最小导航；具体技能入口和绑定版本需要由未来接入机制配置，不能据此认为框架已经安装。

## 读取顺序

1. docs/workflow/state.yaml：迭代、阶段、下一任务与阻塞的导航线索，可能过时，不能单独作为确认或完成依据。
2. docs/project/overview.md 和相关 foundation 文档：当前项目方向与约定。
3. 依据用户明确指定和开轮、暂停、恢复确认，核对相关迭代的 scope、design、tasks、verification 及业务规格；不按编号、最近修改或唯一未标暂停目录猜测当前轮。已有明确依据不重复询问，记录冲突或缺失时只澄清受影响部分。
4. 核对实际代码、环境与文件内容，再决定下一步。

## 最低协作约定

- 空文档表示尚未填写，不等于没有约束或任务已经完成。
- 默认只推进一轮迭代，主 Agent 统一更新正式状态和结果。
- 关键范围、设计和交付按约定确认；实际授权与内容版本需要核对。
- 代码与相关文档保持一致；测试、审查和子任务结果需要实际证据。
- 不把未运行、阻塞或不适用记为通过。
- Git 提交、合并、推送和部署分别按项目明确授权执行。

初始化器未来应仅维护可识别区块，保留项目已有说明。
