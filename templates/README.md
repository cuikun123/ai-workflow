# 业务项目模板

project/ 保存将来初始化业务项目时使用的固定文档骨架。它不是本框架仓库自己的项目记录，也不表示已有初始化器。

完整业务项目布局还包括 .ai-workflow/ 公共框架资源与 .agents/skills/ 完整技能说明，已确认采用方案一直接安装，见 [接入设计](../docs/design/integration.md#调查后确认的业务项目布局)。当前 project/ 仍只保存文档骨架与种子文件；资源组装、技能安装与定位校验等待接入机制实现，不以空占位目录冒充已安装能力。

## 最新空文件约定

- overview、backlog、foundation、specs 索引和 000-foundation 工作文件先建立为零字节文件。
- 项目 AGENTS.md 保留最小导航；state.yaml 保留最小候选起始内容。
- 具体业务规格、后续迭代、发布记录在实际发生时创建。
- releases/.gitkeep 仅用于保留空目录，不是发布记录。

[manifest.json](manifest.json) 显式列出本次模板中的空文件、种子文件和目录占位，供检查和未来实现参考。清单格式本身仍是骨架阶段的内部约定。

## 填充职责

地基填充当前基础约定和本次地基工作记录；需求阶段填写范围、设计和任务；实施与测试记录实际结果；验收后同步当前业务规格；发布时新增实际发布记录。

未来初始化器需按阶段识别空文件；存在文件不代表已有约定、完成或验证通过。

## 状态模板边界

state.yaml 的字段、枚举、版本与兼容策略尚未正式确定。当前文件用于保留讨论方向；不能声称已完成正式 schema 校验或运行集成。

当前没有填充式内容模板或入口安装脚本。spec 内容写法见 [规格设计](../docs/design/spec-format.md)。
